# Documentation style

Write for a specific audience and state the outcome first. Prefer short runnable examples over abstract descriptions. Explain safety and required permissions beside mutating examples. Use stable terms consistently: “script” for `.ds` source, “direct command” for CLI resource operations, “dry-run” for preview, and “force”/“yes” for explicit approval.

When behavior changes, update the relevant reference, at least one example, and the specification/checklist when the change affects a requirement.
